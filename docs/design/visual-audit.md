## Найденные проблемы

### 1. Нет дизайн-системы: только палитра

`mobile/src/theme/` содержит единственный файл `colors.js`. Нет шкалы
типографики (в коде живут размеры 11-32 и веса 600/700/800/900 без правила),
шкалы отступов (8,10,12,14,15,16,20,24 произвольно), шкалы радиусов
(6,8,10,12,14,15,16,17,18,19,20,24,28,48,999 вперемешку), глубины/теней,
состояний компонентов как системы.

Следствие: каждый экран выглядит «своим» продуктом. 15 из 18 экранов содержат
захардкоженные цвета в обход токенов — при смене палитры они разъедутся.

### 2. Захардкоженные «полутона» вместо токенов

| Цвет | Где | Смысл |
|------|-----|-------|
| `#FFF7DE` | Onboarding, Assessment, CaseDetail | фон выбранного варианта |
| `#EAF8EE` | Assessment | фон успеха |
| `#FFF0F0` | Assessment | фон ошибки |
| `#E4D9C8` | AnimatedButton | тень outline-кнопки |
| `#ffffff` | app.json (splash, adaptiveIcon) | не совпадает с фоном `#F6F1E8` |

### 3. Типографика без иерархии

`fontWeight: '900'` используется и для заголовка экрана, и для подписи кнопки, и
для служебных подписей. Нет различия display / title / body / caption:
в `LessonScreen` 21 объявление `fontSize` и 4 разных веса без системы.

### 4. Анимации почти отсутствуют

Reanimated подключён, но из 18 экранов анимации есть только в двух
(`LoginScreen`, `RegisterScreen`). Нет: появления экранов и карточек, перехода
между шагами онбординга, реакции варианта ответа на выбор, анимации прогресса и
XP, движения композиции в сценарии кейса.

Маскот-риг `BearRig` уже содержит полноценную систему состояний
(`correct_big`, `wrong_soft`, `perfect_lesson`, `streak_celebrate`, `level_up`,
`achievement_unlock` и др.), но на экранах по умолчанию используется растровый
`MascotImage` с тремя реакциями (`idle` / `celebrate` / `sad`). Самая
проработанная часть UI не задействована.

### 5. Навигация: 21 маршрут, видимы 4

В `RootNavigator` — 4 таба и 10 стековых экранов. До `AdaptiveLearning`,
`Assessment`, `LearningProgress`, `League`, `Articles`, `Shop`, `Settings`,
`Premium` нет предсказуемого пути из навигации: они открываются только по
случайным ссылкам с других экранов. Единого анимированного перехода нет.

### 6. Состояния ошибок не системны

`Assessment` рисует текст + кнопку, `CaseDetail` — маскот `networkError` + текст,
остальные — спиннер или ничего. Нет общих `ErrorState` / `EmptyState` / `Skeleton`.

### 7. Онбординг не использует анимацию шага

Первый экран продукта: три шага в одном `ScrollView` без анимации перехода,
индикатор шага без анимации, кнопка «Начать путь» не использует общий
`AnimatedButton`, маскот `wave` проигрывается один раз и не реагирует на выбор.

### 8. Assessment и Case flow — визуально разные продукты

Один и тот же паттерн (ситуация → варианты → разбор) оформлен по-разному:
радиусы 15/18 против 16/18/19, разные отступы и способы показа обратной связи,
в `Assessment` нет маскота и реакции на выбор.

### 9. Мелочи

- `CaseDetailScreen`: `minHeight: 130` у строки с маскотом — пузырь «прыгает».
- `PremiumScreen`: 16 объявлений `fontSize` на одном экране.

## Концепция обновления

**Направление: «журнал дела» — тёплая бумага, чернила, золото, один уверенный акцент.**

Палитра рабочая (cream `#F6F1E8`, ink `#1F2A44`, gold `#C9A227`). Менять её на
другую не нужно — нужно превратить в систему и довести до качества на четырёх
ключевых экранах.

### 1. Дизайн-токены (`mobile/src/theme/tokens.js`)

- `colors` — существующая палитра + `surface`, `surfaceAlt`, `goldTint`,
  `successTint`, `errorTint`, `borderSoft`, `shadow`.
- `typography` — 6 ролей: `display` 32/900, `title` 24/900, `heading` 18/800,
  `body` 15/600, `caption` 13/700, `micro` 11/800 + tracking.
- `spacing` — шкала 4/8/12/16/20/24/32; остальные значения не используются.
- `radius` — `sm` 10, `md` 14, `lg` 18, `xl` 24, `pill` 999.
- `elevation` — 3 уровня глубины в стиле Duolingo: нижняя «подошва» элемента,
  а не размытая тень.

4 ключевых экрана переводятся на токены первыми, затем остальные. Хардкод из
таблицы выше заменяется на `goldTint` / `successTint` / `errorTint`.

### Экраны

Переписаны на токены все 18. `LoginScreen` и `RegisterScreen` используют общий
каркас `components/AuthLayout.js` вместо почти построчного дублирования
`KeyboardAvoidingView` + `Confetti` + карточки формы.

### Функциональные блокеры, вскрытые по ходу

Аудит был визуальным, но при разборе экранов нашлись четыре реальных дефекта.
Они исправлены в том же наборе изменений:

| Экран | Дефект | Исправление |
|-------|--------|-------------|
| `LeagueScreen` | таблица лидеров была выдуманным массивом в коде | `GET /gamification/leaderboard` — реальный запрос по лиге |
| `ShopScreen` | покупка за гемы не работала: только haptic и аналитика | `POST /gamification/shop/purchase`, каталог на сервере |

| `ProfileScreen` | пульс уровня срабатывал повторно из-за раннего `return` до записи `prevLevelRef` | запись вынесена перед выходом из эффекта |

### Состояния

Добавлены недостающие ветки: `ArticlesScreen` — ошибка (раньше экран молча
оставался пустым), `CasesScreen` — кнопка «Повторить» в ошибке,
`AdaptiveLearningScreen` — ошибка, повтор и состояние «вопросы закончились».

### Проверено

- `npx eslint src --max-warnings 0` — 0 ошибок, 0 предупреждений;
- `npx expo export --platform web` и `--platform android` — собираются;

### Что осталось за рамками

- 10 компонентов в `components/` всё ещё импортируют `theme/colors`. Файл
  реэкспортирует базовую палитру из токенов, поэтому это безопасно, но
  новые компоненты должны брать цвета из `theme/tokens`.
- Пункты «Концепции обновления» про единые `ErrorState` / `EmptyState` /
  `Skeleton` и анимацию шагов онбординга не реализованы — задачи из
  навигационной части аудита (п.5, п.7) остаются открытыми.

### 2. Motion-система (`mobile/src/theme/motion.js`)

| Примитив | Длительность | Кривая | Где |
|----------|--------------|--------|-----|
| `enter` | 260 ms | `Easing.out(Easing.cubic)` | появление карточек и списков |
| `press` | 90 ms in / 220 ms out | spring (damping 6, stiffness 300) | кнопки |
| `feedback` | 320 ms | spring (damping 12) | правильный / неправильный ответ |
| `celebrate` | 600-900 ms | spring | XP, уровень, идеальный результат |
| `stepTransition` | 300 ms | `Easing.inOut(Easing.quad)` | шаги онбординга |

Правила:

- анимируются только `transform` и `opacity` (UI-поток, без layout-пересчёта);
- при `AccessibilityInfo.isReduceMotionEnabled()` появления идут с `duration: 0`,
  демонстрационные анимации (confetti, прыжок маскота) не запускаются;
- анимация не блокирует действие: кнопка активна сразу, даже если ещё едет.

### 3. Маскот

Использовать существующий `BearRig` (новую систему персонажа не создавать), но
включать его там, где реакция несёт смысл: онбординг, ответ в кейсе, результат.
В остальных местах — лёгкий `MascotImage`.

### 4. Приоритетные экраны

1. **Onboarding** — анимация шагов, реакция маскота на выбор цели, общий `AnimatedButton`.
2. **Assessment** — появление карточки и вариантов, реакция на выбор, общий
   компонент обратной связи, маскот.
3. **Case flow (`CaseDetailScreen`)** — «ситуация → выбор → проверка → разбор»
   с анимацией перехода и реакцией маскота.
4. **Результат и прогресс (`LearningProgressScreen`)** — анимация роста
   компетенций, XP и общего прогресса.

Остальные 14 экранов — после согласования визуального ядра.

## Что не меняется

- навигация (имена роутов и структура стека сохраняются);
- бизнес-логика и вызовы API;
- существующие функции (ничего не удаляется);
- Expo 54 / RN 0.81; новых тяжёлых зависимостей нет — используются уже
  подключённые `react-native-reanimated` и `expo-haptics`;
- при отключённых анимациях приложение работает полностью.

- `ProfileScreen`: радиус `48` рядом с `999` для одного и того же аватара.
