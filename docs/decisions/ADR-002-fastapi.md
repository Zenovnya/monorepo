# ADR-002: FastAPI + SQLAlchemy 2 (async) + Alembic

**Статус:** принято · **Дата:** 2026-10

## Контекст

Нужен API для мобильного клиента: аутентификация по JWT, чтение контента
(сотни вопросов и кейсов), запись прогресса на каждый ответ, геймификация,
платежи, push. Профиль нагрузки — много мелких запросов с телефона при плохой
связи, пики в вечерние часы. Команда небольшая, язык — Python.

## Решение

- **FastAPI** — HTTP-слой, Pydantic-схемы, автогенерируемая OpenAPI-схема.
- **SQLAlchemy 2.0 async** + **asyncpg** — доступ к PostgreSQL.
- **Alembic** — миграции, 24 ревизии.
- Модульная структура: `app/modules/<домен>/{models,schemas,service,routes}.py`.

## Почему

1. **Async под нагрузку «много ожиданий».** Почти весь запрос — это ожидание
   БД. Асинхронный стек убирает простаивающие воркеры; на одной машине это
   заметнее, чем любой микро-оптимизации.
2. **Pydantic как контракт.** Схемы — единственное место, где описано, что
   сервер отдаёт. `response_model` отсекает случайную утечку полей (например,
   `hashed_password`).
3. **OpenAPI бесплатно.** Схема (`/openapi.json`) используется тестами и
   админкой; документация для клиента — `docs/api.md`.
4. **Alembic, а не `create_all`.** Тесты поднимают схему из метаданных, но
   прод меняется только ревизиями: так видно историю и можно откатиться.
5. **Модули, а не слои.** `modules/gamification` целиком отвечает за XP,
   жизни и магазин. Найти «где живёт логика стрика» — один каталог, а не три.

## Следствия

- **Модели — источник правды для схемы БД**, миграции пишутся руками и
  проверяются на sqlite отдельно (в CI нет второго Postgres).
- `default=` в `mapped_column` работает **только при INSERT**: до `flush`
  поля `None`. Это уже приводило к падениям (`None + 1` в SM-2, «все
  напоминания выключены»). Правило: числовые поля задаются явно в сервисе, а
  модели с важными дефолтами имеют `__init__`.
- **Никакой бизнес-логики в роутах**: роут валидирует вход, зовёт сервис,
  переводит доменные исключения в HTTP-коды. Логика в `service.py` тестируется
  без TestClient.
- Синхронные тяжёлые операции (bcrypt) вынесены в `verify_password_async`,
  чтобы не блокировать loop.
- Внешние интеграции (Expo, Resend, ЮKassa) не бросают наружу: сетевой сбой
  логируется и попадает в отчёт, но не превращается в `500`.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Django + DRF | Синхронный ORM по умолчанию, async-поддержка моложе; админка из коробки не нужна — своя уже есть |
| Flask + SQLAlchemy | Нет валидации и OpenAPI из коробки — всё руками, а схем много |
| Litestar / Starlette «голый» | Меньше экосистемы и примеров; выгода в скорости не критична |
| Prisma / Tortoise ORM | Слабее в сложных выборках (лидерборд, очереди ревью) и в миграциях |
