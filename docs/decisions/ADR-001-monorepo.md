# ADR-001: один репозиторий для backend, mobile, admin и infra

**Статус:** принято · **Дата:** 2026-10

## Контекст

Продукт состоит из четырёх частей, которые меняются вместе: FastAPI-сервис,
Expo-приложение, веб-админка контента и инфраструктура (docker, railway,
supabase). Контракт между клиентом и сервером меняется почти в каждом коммите:
новое поле в `/gamification/me`, новый `409` в уроке, новый экран под него.
Контент (кейсы, уроки) лежит JSON-паками и импортируется бэкендом, но правится
людьми, которые видят его в приложении.

## Решение

Один репозиторий (`monorepo`) с каталогами `backend/`, `mobile/`, `admin/`,
`infra/`, `docs/`, `scripts/`. Один CI на все части, одна история коммитов, один
PR на изменение поведения.

## Почему

1. **Атомарность контракта.** Изменение `POST /lexbear/lessons/{id}/complete`
   и перехват нового ответа в `LessonScreen` — один коммит. В отдельных
   репозиториях это два PR, которые нельзя смержить одновременно, и между ними
   прод сломан.
2. **Один CI.** Проверки связаны: миграция без модели ломает тесты, модель без
   миграции — прод. В одном прогоне видно всё сразу.
3. **Контент и код рядом.** `backend/app/content_packs/*.json` меняется вместе
   с обработкой форматов; ревью контента и ревью кода идут в одном PR.
4. **Маленькая команда.** Накладные расходы на несколько репозиториев
   (версии, зависимости, кросс-репо PR) не окупаются.

## Следствия

- CI фильтрует шаги по путям: изменение только в `mobile/` не гоняет pytest.
- Версии зависимостей независимы: `backend/requirements.txt` и
  `mobile/package.json` не связаны.
- Корневой `package.json` — только скрипты-обёртки, своей логики в нём нет.
- Границы модулей держатся договорённостью, а не физическим разделением:
  `mobile/src/api/*` повторяет структуру `backend/app/modules/*` по доменам,
  и это стоит сохранять.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Отдельные репозитории на backend и mobile | Расхождение контракта между PR; кросс-репо изменения требуют координации |
| Монорепо-инструмент (Nx, Turborepo) | Проекты на разных стеках (Python и Node), общего графа сборки нет; выгода не покрывает сложность |
| Один репозиторий с выделенным `packages/shared` | Общий код между Python и JS невозможен; контракт описан `docs/api.md`, а не типами |
